# 围栏数据管理与跨设备迁移

项目继续采用 Kotlin + XML + ViewBinding。新增持久化数据包管理，可在不重新编译 APK 的情况下替换区域数据。

## 使用与迁移

1. 在原设备点击“围栏数据 · 区域列表 / 导入 / 导出”。
2. 通过“区域列表”搜索名称或 ID，查看来源属性、定位多边形、隐藏/显示区域。
3. “编辑数据说明”可设置数据名称、版本/日期和来源，随迁移包一起保存。
4. 选择“导出迁移包”，使用系统文件选择器保存 `FlyRegon-geofences.zip`。
5. 通过 USB、蓝牙或你选择的文件传输渠道将 ZIP 传到新设备。
6. 新设备安装本应用，选择“导入数据”，选中 ZIP，查看摘要并确认。完整校验通过后才会整体替换当前数据。

迁移包包含原始 GeoJSON（含各 Feature 的来源、年份、许可与 preview_only 等属性）、数据名称、版本、来源说明、各区域隐藏 ID。不会包含天地图 Key、账户凭据、底图瓦片缓存。全局临时显示开关、地图中心和长按标记不属于数据包。

文件选择器不需要全盘存储权限，取消导入/导出不改变当前数据。导出失败可能在所选位置留下不完整文件，应用会报错；应重新导出成功后再转移。

## 数据更新

也可直接导入 UTF-8 GeoJSON FeatureCollection（可带 UTF-8 BOM），兼容原 Python 工具生成的 `all_geofences.geojson`。导入为**整体替换**，不与旧数据合并。不支持直接导入原始工具 ZIP 或含其他文件的预览 ZIP；请选其中的合并 GeoJSON。

- 必须为 RFC 7946 WGS84 经纬度坐标，顺序 [经度, 纬度]，不接受旧 crs 字段。
- 支持 Polygon / MultiPolygon、孔洞、重叠区域；日期线跨越必须预先切分。
- Feature id 或 properties.geofence_id 必填且唯一，最长 128 字符；properties.name_zh 可作为显示名，最长 160 字符。
- 最多 500 个区域、合计 100000 个坐标点；GeoJSON 最多 7 MB，ZIP 压缩文件及解压总量最多 8 MB。超过限制需分数据集或先预处理，避免大数据阻塞地图。
- 会检查闭环、拓扑、坐标范围、重复 ID，拒绝损坏/不支持的数据。
- 列表定位多岛区域时优先显示面积最大的部分，避免俄罗斯跨日期线时缩放到全世界；区域总览可查看全部。
- 红色表示当前数据区域，橙色表示长按命中或列表定位选中。单区隐藏与全局开关只控制绘制，查询仍覆盖当前数据集全部区域。

## 迁移包 v1 格式

ZIP 根目录只允许两个文件，不进行路径解压：

```text
manifest.json
geofences.geojson
```

manifest 示例（SHA256 按实际 GeoJSON UTF-8 文件字节计算）：

```json
{
  "schemaVersion": 1,
  "name": "14 国行政区预览",
  "version": "NaturalEarth-110m-preview-v1",
  "source": "Natural Earth · 1:1.1 亿 · 仅预览",
  "featureCount": 14,
  "sha256": "GeoJSON文件字节的SHA256十六进制摘要",
  "hiddenIds": ["country_USA"]
}
```

SHA256 用于检测 GeoJSON 文件损坏，不是来源认证或数字签名。拒绝未知格式版本、摘要/数量不一致、无效显示 ID、未知/重复 ZIP 条目和超限解压数据。原始属性完整保留，导入不会自动将行政区数据升级为官方禁飞区数据。

## 本地与系统迁移

当前数据保存于应用私有 files/geofences/active-geofences.zip，重启后自动加载。写入使用 Android AtomicFile，失败回滚；文件读写和解析在串行后台线程完成。跨 Activity 实例的存储操作通过共享锁串行执行。

已将该目录加入 Android 备份和设备转移规则。系统迁移是否执行取决于用户设置、系统服务与厂商实现；独立 ZIP 导入/导出可手动迁移，不依赖系统备份。卸载前应先导出。

## 数据适用范围

随 APK 内置的仍是 14 国低精度行政区预览，并未新增或声称认证航空限制空域。需要更精细数据时可导入经确认的 GeoJSON；高精度行政边界本身仍不等同于禁飞规则。当前模型处理水平二维区域，不执行高度、有效时段、GPS 缓冲或飞控限制。未命中不表示允许飞行。

